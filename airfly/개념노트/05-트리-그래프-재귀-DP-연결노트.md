# 05. 기초에서 트리·그래프·DP로 넘어가는 연결 노트

[학습 지도](../README.md) · 이전: [풀이 패턴](04-정렬-탐색-수학-구간-패턴.md) · 다음: [테스트와 복습](06-테스트-디버깅-복습.md)

이 장은 참고 PDF의 범위를 이어 주는 선택 심화다. 7시간 안에 모두 구현할 목표는 아니다. 50문제 중 33·45·47은 다음 단계로 넘어가는 짧은 연결 연습이며, 전체 난이도는 공식 플랫폼 등급 인증이 아닌 자체 Lv.1 목표 구성이다.

## 1. 연결리스트: 값을 옮기지 않고 연결을 바꾼다

각 노드가 값과 다음 노드를 가리키는 참조를 가진다. 배열처럼 i번째를 바로 읽는 구조가 아니다.

```text
head → A → B → C → null
A 뒤에 X 삽입:
X.next = A.next
A.next = X
결과: A → X → B → C
```

두 대입문의 순서를 바꾸면 원래 다음 노드를 잃거나 잘못된 연결을 만들 수 있다. 변경 전에 어떤 연결을 보존해야 하는지 그림으로 확인한다.

```js
const head = { value: 'A', next: { value: 'B', next: null } };
const inserted = { value: 'X', next: head.next };
head.next = inserted;
const values = [];
for (let node = head; node !== null; node = node.next) values.push(node.value);
if (JSON.stringify(values) !== '["A","X","B"]') throw new Error('연결 삽입 오류');
```

원하는 앞 노드를 이미 알면 연결 변경은 O(1)이다. 앞 노드를 찾기 위해 처음부터 읽어야 한다면 전체 작업은 O(n)이 될 수 있다. ‘연결리스트 삽입은 항상 O(1)’이라고만 외우지 않는다.

이중 연결리스트는 prev도 저장한다. 앞뒤 이동이 가능하지만 삽입·삭제 때 양쪽 연결을 모두 맞춰야 한다. PDF의 대규모 편집기 문제는 이러한 구조가 의미 있는 예다. Lv.1 기초 문제에 매번 직접 구현할 필요는 없다.

## 2. 재귀: 같은 질문을 더 작은 입력에 맡긴다

재귀 함수를 설계할 때는 세 문장을 적는다.

1. 이 함수는 무엇을 반환하는가?
2. 더 나누지 않고 답할 최소 입력은 무엇인가?
3. 다음 호출의 입력이 어떻게 작아지는가?

```js
function factorial(n) {
  if (n <= 1) return 1;
  return n * factorial(n - 1);
}
if (factorial(4) !== 24 || factorial(0) !== 1) throw new Error('재귀 오류');
```

factorial(4)는 `4*factorial(3)`을 기다리고, 그 아래에서 3,2,1 순으로 요청이 쌓인다. 1의 답이 나온 뒤 2→6→24 순으로 계산이 돌아온다.

종료 조건만 있다고 안전한 것이 아니다. n이 정말 줄어들어 종료 조건에 도달하는지 봐야 한다. 또 JS는 매우 깊은 재귀에서 호출 스택 한도를 넘을 수 있다. 깊이가 큰 입력이면 반복문과 명시적인 스택을 검토한다.

## 3. 트리: 순환 없는 계층

루트는 시작 노드, 부모·자식은 바로 연결된 위아래 관계, 리프는 자식 없는 노드다. 일반적인 트리는 연결되어 있고 순환이 없다. 노드가 V개라면 간선은 V-1개다.

이진 트리는 자식이 최대 두 개라는 뜻이다. 값이 정렬되어 있다는 뜻은 아니다.

| 이름 | 정확히 확인할 속성 |
| --- | --- |
| 이진 트리 | 자식이 최대 2개 |
| 정 이진 트리(full/proper) | 각 노드의 자식 수가 0 또는 2 |
| 포화 이진 트리(perfect) | 모든 내부 노드의 자식이 2개이고 모든 리프 깊이가 같음 |
| 완전 이진 트리(complete) | 마지막 층 외에는 가득 차고, 마지막 층은 왼쪽부터 채움 |

참고 PDF의 full과 포화 표기는 혼동 여지가 있다. 용어 번역이 자료마다 다를 수 있으므로 실제 구조 조건으로 구별하자.

### 순회는 방문 시점의 차이

```text
    A
   / \
  B   C
 / \
D   E

전위: 현재 → 왼쪽 → 오른쪽 = A B D E C
중위: 왼쪽 → 현재 → 오른쪽 = D B E A C
후위: 왼쪽 → 오른쪽 → 현재 = D E B C A
```

```js
function preorder(node) {
  if (node === null) return [];
  return [node.value, ...preorder(node.left), ...preorder(node.right)];
}
const leaf = value => ({ value, left: null, right: null });
const root = { value: 'A', left: leaf('B'), right: leaf('C') };
if (JSON.stringify(preorder(root)) !== '["A","B","C"]') throw new Error('전위 순회 오류');
// ponytail: 작은 트리의 순서 설명용 배열 결합. 큰 트리는 하나의 결과 배열에 push하도록 변경한다.
```

위 코드는 흐름을 보여 주는 작은 예시다. 재귀마다 결과 배열을 합치므로 편향 트리에서는 복사 비용이 O(V²)까지 커질 수 있다. 큰 트리에서는 결과 배열 하나에 방문할 때 push하면 노드 순회 자체는 O(V), 호출 공간은 트리 높이 O(H)가 된다.

## 4. 이진 탐색 트리와 정렬 배열은 다르다

이진 탐색 트리(BST)는 각 노드의 왼쪽 부분에 더 작은 값, 오른쪽 부분에 더 큰 값이 놓이는 규칙을 가진다. 중복을 허용한다면 어느 쪽에 둘지 또는 개수를 따로 저장할지 규칙이 추가로 필요하다.

값을 찾을 때 현재 노드와 비교해 왼쪽이나 오른쪽으로 간다. 시간은 트리 높이 H에 비례한다. 균형이 좋으면 O(log V), 일렬로 기울면 O(V)다. 그냥 BST라는 이유만으로 항상 빠르다고 말하면 안 된다.

삭제는 리프, 자식 하나, 자식 둘의 경우를 나눈다. 자식 둘이면 후계자 등의 값으로 대체하고 연결을 다시 맞춰야 한다. 지금 단계에서는 47번 정렬 배열 이분 탐색의 범위 제거 논리를 먼저 익힌다.

## 5. 그래프: 관계를 표현한다

정점은 대상, 간선은 연결이다. 사람과 친구 관계, 역과 노선, 격자의 통로를 그래프로 볼 수 있다.

방향 그래프는 A→B가 B→A를 뜻하지 않는다. 무방향 그래프는 양쪽 연결이다. 가중치는 이동 시간·비용처럼 간선에 붙는 수다.

| 표현 | 기억하는 것 | 공간 | 장점 |
| --- | --- | --- | --- |
| 인접 행렬 | 모든 두 정점의 연결 여부 | O(V²) | 특정 간선 확인이 간단 |
| 인접 리스트 | 각 정점의 실제 이웃 | O(V+E) | 간선이 적을 때 효율적 |

인접 행렬은 간선 수와 관계없이 V² 칸을 쓴다. 특히 간선이 적은 희소 그래프에서 낭비가 크다. 간선이 많다는 이유만으로 행렬이 항상 비효율적이라고 단정하지 않는다.

```text
무방향 간선: 0-1, 0-2, 1-3
인접 리스트:
0: [1,2]
1: [0,3]
2: [0]
3: [1]
```

무방향 간선은 양쪽 목록에 넣는다. 방문 표시가 없으면 0→1→0→1로 계속 왕복할 수 있다.

## 6. DFS와 BFS의 선택

DFS는 한 방향으로 깊게 진행한다. 연결 여부, 도달 가능한 노드 수 등을 확인할 때 사용할 수 있다. 재귀 또는 명시적 스택을 사용한다.

BFS는 가까운 층부터 진행한다. 모든 간선 비용이 같을 때 최소 간선 수를 구하기에 적합하다. 일반적인 가중치 최단 경로를 무조건 BFS로 풀면 안 된다.

```js
function distances(graph, start) {
  const distance = Array(graph.length).fill(-1);
  const queue = [start];
  distance[start] = 0;
  let head = 0;
  while (head < queue.length) {
    const current = queue[head++];
    for (const next of graph[current]) {
      if (distance[next] !== -1) continue;
      distance[next] = distance[current] + 1;
      queue.push(next);
    }
  }
  return distance;
}
const graph = [[1, 2], [0, 3], [0], [1], []];
if (JSON.stringify(distances(graph, 0)) !== '[0,1,1,2,-1]') throw new Error('BFS 거리 오류');
```

방문은 큐에 넣을 때 표시한다. 꺼낼 때까지 기다리면 여러 이웃이 같은 노드를 중복으로 넣을 수 있다. 위 예시에서 distance=-1은 미방문과 도달 불가 표시를 겸한다.

인접 리스트에서 BFS/DFS의 전체 순회 비용은 O(V+E)다. 큐나 스택이 있다는 이유로 O(V)라고만 쓰면 이웃 간선 확인을 빠뜨린다.

48번은 이웃 네 칸만 세므로 BFS가 필요 없다. ‘모든 연결된 빈자리 수’로 질문이 바뀌면 방문 표시와 탐색이 필요해진다.

## 7. 힙: 계속 바뀌는 후보 중 최우선

최소 힙에서는 부모 값이 자식 값 이하라 루트가 전체 최솟값이다. 형제 사이 또는 서로 다른 부분 트리 사이의 정렬은 보장하지 않는다. 힙 배열 전체가 오름차순이라는 뜻이 아니다.

0 기준 배열에서 부모는 floor((i-1)/2), 왼쪽 자식은 2i+1, 오른쪽은 2i+2다. 루트에는 부모가 없다.

삽입은 끝에 추가한 뒤 부모보다 작으면 위로 올린다. 삭제는 루트를 꺼내고 마지막 원소를 루트에 둔 뒤, 더 작은 자식보다 크면 그 자식과 바꿔 내려간다.

```text
최소 힙 [2,5,3,9]에서 1 삽입:
[2,5,3,9,1] → 부모 5와 교환 → [2,1,3,9,5]
→ 부모 2와 교환 → [1,2,3,9,5]
```

루트 확인 O(1), 삽입·루트 삭제 O(log n). 참고 PDF의 최소 힙 내려가기 설명은 ‘현재 값이 더 작은 자식보다 클 때 교환’으로 이해해야 한다.

처음 한 번 정렬해 읽기만 한다면 정렬 배열로 충분할 수 있다. 값이 계속 들어오고 매번 최솟값을 꺼내야 할 때 힙의 필요성이 커진다. Lv.1 기본 문제에 힙 구현을 먼저 들고 들어갈 필요는 없다.

## 8. DP: 작은 문제의 답을 재사용

DP를 시작할 때 코드보다 상태 정의를 먼저 쓴다.

```text
상태: ways[i] = i칸을 정확히 오르는 순서 수
기저: ways[0]=1, ways[1]=1
전이: 마지막 1칸이면 ways[i-1], 마지막 2칸이면 ways[i-2]
계산 순서: i를 작은 값부터 증가
최종 답: ways[n]
```

ways[0]=1은 ‘아무 이동도 안 하는 방법 하나’라는 뜻이다. 의미 없이 초기값만 암기하면 변형 문제에서 막힌다.

Top-down은 필요한 작은 문제를 재귀로 요청하고 저장한다. Bottom-up은 작은 입력부터 순서대로 계산한다. 둘 다 반복되는 하위 문제의 결과를 재사용한다.

### 그리디 실패 뒤의 다음 선택: 일반 동전

동전 [1,3,4]로 6을 만들 때 그리디는 실패했다. `dp[x]=x원을 만드는 최소 동전 수`로 두고 마지막 동전 c를 선택하면 `dp[x-c]+1`을 후보로 삼을 수 있다.

```js
function minCoins(coins, amount) {
  const dp = Array(amount + 1).fill(Infinity);
  dp[0] = 0;
  for (let value = 1; value <= amount; value++) {
    for (const coin of coins) {
      if (coin <= value) dp[value] = Math.min(dp[value], dp[value - coin] + 1);
    }
  }
  return dp[amount] === Infinity ? -1 : dp[amount];
}
if (minCoins([1, 3, 4], 6) !== 2) throw new Error('그리디 반례 처리 오류');
if (minCoins([2], 3) !== -1 || minCoins([2], 0) !== 0) throw new Error('불가능/기저 오류');
```

각 마지막 동전을 전부 고려하므로 최적 선택도 후보에 포함된다. 시간 O(amount×동전 종류 수), 공간 O(amount). 금액이 10억이면 이 배열은 부적절하므로 제한을 먼저 확인한다.

PDF의 LIS, 연속 선택 제한, 집 선택 문제도 ‘현재 무엇까지 고려한 최적값인가’를 정의해야 한다. 이 장의 목적은 그 문제들을 한 번에 암기하는 것이 아니라 상태·기저·전이·순서·답이라는 다섯 질문을 익히는 것이다.
