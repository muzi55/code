# 04. 자주 쓰는 풀이 패턴과 선택 근거

[학습 지도](../README.md) · 이전: [자료구조](03-배열-해시-스택-큐.md) · 다음: [심화 연결](05-트리-그래프-재귀-DP-연결노트.md)

## 1. 시간복잡도를 실제 반복과 연결하기

O는 입력이 커질 때 작업량이 얼마나 증가하는지 나타내는 표기다. O(n)이 ‘정확히 n번’이라는 뜻은 아니며, 2n+10처럼 선형 증가하는 작업도 포함한다.

| 구조 | 횟수 | 복잡도 |
| --- | --- | --- |
| 원소 n개를 한 번 순회 | n | O(n) |
| 순회 두 번을 차례로 실행 | n+n | O(n) |
| 각 원소마다 모든 원소 확인 | n×n | O(n²) |
| i<j 쌍 | n(n-1)/2 | O(n²) |
| 모든 원소에서 고정 4방향 확인 | 4n | O(n) |
| 매번 후보를 절반으로 감소 | 약 log₂n | O(log n) |
| 정렬 후 전체 순회 | n log n+n | 통상 O(n log n) |

입력이 두 개면 n,m을 따로 둔다. 길이 n과 m의 배열을 각각 순회하면 O(n+m), 모든 조합이면 O(nm)이다. 행렬 R×C 전체 순회는 O(RC)이며 입력 원소 수 자체가 RC개다.

공간복잡도는 기억하는 상태의 크기다. 결과 배열을 포함하는지 제외하는지 명시하자. 필터링은 결과를 제외하면 변수 몇 개지만 반환 배열은 최악 n개 원소를 담는다.

## 2. 완전탐색: 후보를 빠짐없이 검사

먼저 후보가 무엇인지 정한다. 값 하나인지, 두 인덱스인지, 세 인덱스인지에 따라 반복 범위가 달라진다.

```js
function pairIndices(n) {
  const result = [];
  for (let i = 0; i < n; i++) {
    for (let j = i + 1; j < n; j++) result.push([i, j]);
  }
  return result;
}
if (JSON.stringify(pairIndices(3)) !== '[[0,1],[0,2],[1,2]]') throw new Error('조합 오류');
```

`i<j`는 같은 원소 재사용과 순서만 다른 쌍을 동시에 막는다. 값 `[1,1,2]`에서 첫 1과 둘째 1은 서로 다른 인덱스이므로 선택할 수 있다.

완전탐색에서 꼭 설명할 것: 가능한 답이 모두 후보에 들어 있는가, 중복 후보를 세고 있지 않은가, 최대 후보 수가 얼마인가.

## 3. 정렬: 어떤 관계를 드러내는가

정렬은 순위, 중앙값, 가까운 값, 싼 순서 같은 질문을 단순하게 만든다. 정렬 자체가 목적이 아니라, 정렬 후 어떤 판단이 쉬워지는지 설명해야 한다.

28번의 최소 차이는 정렬 후 인접쌍만 보면 된다. 세 값 a≤b≤c에서 c-a=(c-b)+(b-a)이므로 멀리 떨어진 차이가 모든 인접 차이보다 작아질 수 없다.

22번은 점수 내림차순, 동률일 때 이름 오름차순이다. 우선순위를 자연어로 먼저 쓰고 비교 함수에 같은 순서로 옮긴다.

### 정렬 알고리즘을 직접 구현해야 하나

일반 문제에서는 JS 내장 정렬을 적절한 비교 함수와 함께 사용한다. 학습 목적의 요약은 아래 정도면 된다.

| 알고리즘 | 핵심 생각 | 일반적인 시간 |
| --- | --- | --- |
| 버블 | 이웃 비교·교환 반복 | 평균/최악 O(n²), 조기 종료 구현은 최선 O(n) 가능 |
| 선택 | 남은 부분 최솟값을 앞에 | O(n²) |
| 삽입 | 앞의 정렬된 부분에 삽입 | 평균/최악 O(n²), 정렬된 입력 최선 O(n) |
| 병합 | 둘로 나누고 정렬한 두 부분 결합 | O(n log n) |
| 퀵 | 피벗 기준으로 분할 | 평균 O(n log n), 최악 O(n²) |

내장 Array.sort의 정확한 알고리즘과 시간·공간은 구현에 달려 있다. 문서의 정렬 복잡도는 통상적인 비교 정렬 모델로 설명한다.

참고 PDF의 병합 예시는 앞에서 shift로 꺼낸다. 병합의 O(n log n) 분석을 구현에 적용하려면 합치는 과정이 선형이어야 하므로, 큰 배열에서는 두 인덱스로 읽는 방식을 사용해야 한다.

## 4. 투 포인터: 이동할 근거가 있어야 한다

두 인덱스를 사용한다고 자동으로 O(n)이 되는 것은 아니다. 두 포인터가 합쳐서 몇 번 움직이는지 살핀다.

09번 회문은 양끝의 문자를 비교해 안쪽으로 들어간다. 정렬이 필요 없다. 목표는 대칭 비교다.

29번 합 문제는 정렬이 필요하다. 작은 합이면 왼쪽 값을 더 크게, 큰 합이면 오른쪽 값을 더 작게 바꾼다. 잘못된 이동으로 후보를 버리면 정답을 놓칠 수 있다.

```text
정렬된 [1,3,4,8], target=7
1+8=9: 너무 큼. 8은 다른 더 큰 왼쪽 값과도 안 됨 → 오른쪽 이동
1+4=5: 너무 작음. 1은 다른 더 작은 오른쪽 값과도 안 됨 → 왼쪽 이동
3+4=7: 성공
```

선택 기준: 입력이 정렬되어 있는가, 한쪽을 버리는 이유가 있는가, 같은 인덱스를 두 번 쓰지 않는가.

## 5. 슬라이딩 윈도: 고정 길이 구간의 재사용

40번의 구간 길이는 정확히 k다. 오른쪽으로 한 칸 움직일 때 맨 왼쪽 하나가 빠지고 오른쪽 하나가 들어온다.

```text
원본: [2,-1,3,4], k=2
창 [2,-1] 합 1
창 [-1,3] 합 1-2+3=2
창 [3,4] 합 2-(-1)+4=7
```

고정 길이 합은 음수가 있어도 갱신식이 성립한다. 하지만 ‘합이 목표보다 크면 왼쪽을 줄인다’ 같은 가변 길이 전략은 원소가 음수일 때 단조성이 깨질 수 있다. 서로 다른 윈도 문제의 조건을 혼동하지 않는다.

## 6. 누적합: 앞부분을 저장해 중간을 얻기

prefix[i]를 ‘처음 i개 합’으로 정의한다. prefix[0]=0을 두면 시작이 0인 구간도 특별 처리 없이 계산한다.

```js
function rangeSum(values, left, right) {
  const prefix = [0];
  for (const value of values) prefix.push(prefix[prefix.length - 1] + value);
  return prefix[right + 1] - prefix[left];
}
if (rangeSum([2, 4, 1, 3], 1, 3) !== 8) throw new Error('구간 합 오류');
if (rangeSum([7], 0, 0) !== 7) throw new Error('한 칸 오류');
```

위 코드는 한 번의 질문을 보여주는 예시다. 실제 39번처럼 질문이 많으면 prefix를 한 번만 만들고 모든 질문에 공유해야 한다.

원소를 바꾸면 그 뒤의 누적합도 바뀐다. 갱신과 질의가 섞인 큰 문제에는 단순 누적합만으로 충분하지 않을 수 있다. 지금은 고정 배열에 대한 구간 질문부터 익힌다.

### 2차원 확장 원리

P[r][c]를 처음 r행, 처음 c열로 이루어진 직사각형의 합으로 정의한다. 맨 윗줄과 왼쪽 열은 0이다.

```text
P[r+1][c+1] = A[r][c] + P[r][c+1] + P[r+1][c] - P[r][c]

(r1,c1)~(r2,c2), 양끝 포함:
P[r2+1][c2+1] - P[r1][c2+1] - P[r2+1][c1] + P[r1][c1]
```

위와 왼쪽을 더하면 겹치는 왼쪽 위 영역을 두 번 더하므로 한 번 빼준다. 구간을 구할 때는 위와 왼쪽을 빼면서 겹친 부분을 두 번 빼게 되므로 한 번 더한다. 참고 PDF의 마지막 문제로 가기 전, 39번의 ‘앞부분 빼기’를 먼저 이해하자.

## 7. 이분 탐색: 후보 절반 제거

47번은 오름차순 중복 없는 배열에서 값의 위치를 찾는다. `[left,right]`를 양끝 포함 후보 구간으로 정했다면 빈 구간 조건은 left>right다.

| 중간 값 | 판단 | 새 범위 |
| --- | --- | --- |
| target과 같음 | 발견 | 즉시 반환 |
| target보다 작음 | 중간 이하에는 답 없음 | left=mid+1 |
| target보다 큼 | 중간 이상에는 답 없음 | right=mid-1 |

left=mid처럼 중간을 남기면 범위가 줄지 않는 경우가 있다. 종료 조건만 외우지 말고 한 칸 구간에서 손으로 실행해 보자.

이분 탐색으로 답의 숫자 자체를 찾는 문제도 있다. 이 경우 ‘이 숫자에서 가능하다면 더 큰 숫자에서도 가능한가?’ 같은 단조 판정이 필요하다. PDF의 생산 시간 문제는 이 심화 형태다. 47번을 익힌 뒤 확장한다.

## 8. 약수·소수·최대공약수

약수는 n%d===0인 양의 d다. d가 약수면 n/d도 약수이므로 작은 쪽만 검사할 수 있다. 제곱수에서는 d와 n/d가 같아 한 번만 센다.

소수는 2 이상이고 1과 자기 자신 외의 약수가 없는 수다. 0과 1은 소수가 아니다. 약수 후보를 √n까지 검사하면 충분한 이유는 합성수의 두 인수가 모두 √n보다 클 수 없기 때문이다.

여러 수를 한꺼번에 판정하면 체를 쓴다. 살아 있는 p의 배수를 p*p부터 지운다. p보다 작은 배수 인수는 이전 단계에서 이미 처리했다.

최대공약수는 `gcd(a,b)=gcd(b,a%b)`로 줄인다. a=qb+r에서 a,b를 나누는 수는 r도 나누고, b,r을 나누는 수는 a도 나누기 때문이다. 최소공배수는 `(a/gcd)*b`다.

수학 문제에서도 공식보다 입력 범위, 0과 1의 처리, 제곱 경계, 최종 곱의 안전 범위를 먼저 확인한다.

## 9. 그리디: 지금의 선택을 정당화하기

그리디는 현재 좋아 보이는 선택을 확정하며 진행한다. 정확한 이유가 있어야 한다.

25번에서 개수를 최대화할 때 모든 물건의 가치가 ‘한 개’로 같다. 비싼 물건을 더 싼 물건으로 바꾸면 개수는 같고 비용은 감소한다. 따라서 가장 싼 것부터 고르는 근거가 있다.

49번에서는 동전 단위가 배수 체계를 이루어 작은 동전 여러 개를 큰 동전 하나로 교환할 수 있다. 임의의 동전 집합에는 같은 논리가 적용되지 않는다.

반례를 먼저 찾아 보자. [1,3,4] 동전으로 6을 만들 때 4부터 고르면 3개, 3+3이면 2개다. ‘가장 큰 동전을 고르면 늘 최적’이라는 주장은 이 작은 입력 하나로 깨진다.

## 10. 패턴 선택 연습

- n=40에서 세 개 선택 → 조합 수를 계산한 뒤 완전탐색 검토.
- 정렬된 10만 개에서 값 하나 찾기 → 이분 탐색 검토.
- 고정 배열에 구간 합 10만 번 → 누적합 검토.
- 길이 10만에서 연속 정확히 7개 최대 합 → 고정 윈도 검토.
- 두 값 합 존재, 정렬되지 않음 → 보완값 Set 검토.
- 가장 최근 결제를 취소 → 스택 검토.

각 답에 ‘왜 다른 방법이 필요하지 않은가’까지 설명할 수 있으면 패턴을 외운 것이 아니라 판단한 것이다.
