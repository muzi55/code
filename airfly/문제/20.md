# 20. 두 번호의 서로 다른 합

목표: 쌍의 중복과 결과 값의 중복을 따로 제거한다.  
권장 시간: 12~18분 · JS 함수형 문제 · 자체 제작 Lv.1 목표 연습

## 문제

서로 다른 두 인덱스의 원소를 더해 만들 수 있는 합을 중복 없이 오름차순 반환하라.

### 입력·반환·제한

길이 2~100. 원소 0~1,000 정수.

### 예시

- 입력 인자: `[[1,2,3]]`
- 반환값: `[3,4,5]`
- 설명: 1+2=3,1+3=4,2+3=5다.

## 코딩 전에 직접 적기

1. 반환해야 하는 것은 값, 개수, 위치, 배열 중 무엇인가?
2. 아래 첫 예시를 종이에 풀면 무엇을 기억해야 하는가?
3. 떠오른 풀이의 최대 반복 횟수를 제한과 비교해 보자.
4. 변수마다 “지금까지 처리한 무엇”인지 한 문장으로 쓰자.
5. 정답 코드 전에 아래 테스트 중 두 개를 손으로 계산하자.

함수 형태: `solution(nums)`. 직접 만든 JS 파일에서 구현하고 마지막에 `module.exports = solution;`을 붙이면 테스트할 수 있다.

## 1. 문제를 계산으로 번역하기

i<j인 모든 쌍의 합을 Set에 넣는다.

## 2. 첫 풀이를 평가하고 방법 고르기

최대 4,950쌍이므로 이중 반복문이 충분하다. target이 없으므로 하나의 보완값만 찾는 19번 방식을 그대로 쓸 수 없다.

## 3. 손으로 실행해 보기

[1,2,3]: (0,1)→3, (0,2)→4, (1,2)→5. [1,1,2]는 2와 3만 남는다.

## 4. 구현 순서와 맞는 이유

1. i를 앞 인덱스로 고른다.
2. j는 i+1부터 고른다.
3. 합을 Set에 넣고 마지막에 숫자 정렬한다.

i<j가 서로 다른 두 인덱스의 조합을 한 번씩 열거한다. Set은 다른 조합에서 생긴 같은 합을 합친다.

## 5. JavaScript 정답

<!-- solution -->
```js
function solution(nums) {
  const sums = new Set();
  for (let i = 0; i < nums.length; i++) {
    for (let j = i + 1; j < nums.length; j++) sums.add(nums[i] + nums[j]);
  }
  return [...sums].sort((a, b) => a - b);
}
```

코드를 다시 읽을 때 각 변수와 갱신문을 위의 손풀이에 연결하자. 코드를 닫고 “어떤 정보만 남겼는가”를 설명한 뒤 직접 재작성한다.

## 6. 실수와 반례

j=i이면 같은 원소를 두 번 쓰게 된다. 같은 값의 서로 다른 두 원소는 사용할 수 있다.

## 7. 복잡도

k=서로 다른 합 수. 시간 O(n²+k log k), 공간 O(k). 정렬은 통상 모델.
