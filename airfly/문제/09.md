## 문제

code를 앞에서 읽으나 뒤에서 읽으나 같으면 true, 아니면 false를 반환하라. 대소문자를 구분한다. 빈 문자열도 회문이다.

### 입력·반환·제한

길이 0~100,000. 영문 대소문자와 숫자.

### 예시

- 입력 인자: `["ABBA"]`
- 반환값: `true`
- 설명: ABBA는 양끝 A/A, 안쪽 B/B가 모두 같다.

## 코딩 전에 직접 적기

1. 반환해야 하는 것은 값, 개수, 위치, 배열 중 무엇인가?
2. 아래 첫 예시를 종이에 풀면 무엇을 기억해야 하는가?
3. 떠오른 풀이의 최대 반복 횟수를 제한과 비교해 보자.
4. 변수마다 “지금까지 처리한 무엇”인지 한 문장으로 쓰자.
5. 정답 코드 전에 아래 테스트 중 두 개를 손으로 계산하자.

함수 형태: `solution(code)`. 직접 만든 JS 파일에서 구현하고 마지막에 `module.exports = solution;`을 붙이면 테스트할 수 있다.

## 1. 문제를 계산으로 번역하기

대칭 위치가 하나라도 다르면 실패. 모두 같으면 성공이다.

## 2. 첫 풀이를 평가하고 방법 고르기

뒤집은 문자열을 만들어도 되지만 양끝 인덱스만 이동하면 추가 배열 없이 검사한다. 이 투 포인터는 정렬을 요구하지 않는다.

## 3. 손으로 실행해 보기

ABBA: left=0,right=3에서 A=A. 1,2에서 B=B. 2,1이 되어 교차하면 종료.

## 4. 구현 순서와 맞는 이유

1. 양끝 인덱스를 둔다.
2. 다르면 즉시 false.
3. 같으면 두 인덱스를 안쪽으로 이동한다.
4. 만났거나 교차하면 true.

이미 검사한 바깥쪽 쌍은 모두 같다. 마지막에 미검사 쌍이 없으므로 전체가 대칭이다.

## 5. JavaScript 정답

<!-- solution -->
```js
function solution(code) {
  let left = 0;
  let right = code.length - 1;
  while (left < right) {
    if (code[left] !== code[right]) return false;
    left++;
    right--;
  }
  return true;
}
```

코드를 다시 읽을 때 각 변수와 갱신문을 위의 손풀이에 연결하자. 코드를 닫고 “어떤 정보만 남겼는가”를 설명한 뒤 직접 재작성한다.

## 6. 실수와 반례

홀수 길이의 중앙 글자는 자기 자신이라 검사할 필요 없다. 'Aa'는 false다.

## 7. 복잡도

n=길이. 시간 O(n), 추가 공간 O(1).

`args`는 함수 인자 목록이다. 배열 하나를 받는 함수는 `[[...]]`, 두 인자를 받으면 `[첫째, 둘째]`로 기록한다. 각 `name`은 무엇을 확인하는지 설명한다.

```json
    "expected": true

    "args": [
      "A1A"
    ],
    "expected": true
  },
  {
    "name": "대소문자 다름",
    "args": [
      "Aa"

    "expected": false

    "name": "빈 문자열",
    "args": [
      ""
    ],
    "expected": true
  },
  {
    "name": "내부 불일치",
    "args": [
      "ABCA"
    ],
    "expected": false
  }
]
```
