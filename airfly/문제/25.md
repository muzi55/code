## 문제

각 간식을 최대 하나씩 살 수 있다. 총 가격이 budget 이하가 되도록 가장 많은 개수를 사면 몇 개인지 반환하라.

### 입력·반환·제한

길이 0~100,000, 가격 1~10,000 정수, budget은 0~1,000,000,000.

### 예시

- 입력 인자: `[[4,1,3,2],6]`
- 반환값: `3`
- 설명: 가격 1,2,3을 사면 합 6으로 3개다.

## 코딩 전에 직접 적기

1. 반환해야 하는 것은 값, 개수, 위치, 배열 중 무엇인가?
2. 아래 첫 예시를 종이에 풀면 무엇을 기억해야 하는가?
3. 떠오른 풀이의 최대 반복 횟수를 제한과 비교해 보자.
4. 변수마다 “지금까지 처리한 무엇”인지 한 문장으로 쓰자.
5. 정답 코드 전에 아래 테스트 중 두 개를 손으로 계산하자.

함수 형태: `solution(prices, budget)`. 직접 만든 JS 파일에서 구현하고 마지막에 `module.exports = solution;`을 붙이면 테스트할 수 있다.

```sh
node airfly/test.cjs 25 airfly/practice.cjs
```

## 1. 문제를 계산으로 번역하기

싼 간식부터 예산 안에서 담는다.

## 2. 첫 풀이를 평가하고 방법 고르기

비싼 간식을 선택한 자리를 더 싼 것으로 바꾸면 개수는 같고 비용은 늘지 않는다. 그래서 k개를 가장 싸게 사는 방법은 가장 싼 k개다.

## 3. 손으로 실행해 보기

[4,1,3,2],budget=6 → [1,2,3,4]. 남은 예산 6→5→3→0. 4는 못 사므로 3개.

## 4. 구현 순서와 맞는 이유

1. 복사해서 가격순 정렬한다.
2. 남은 예산보다 비싸면 끝낸다.
3. 살 수 있으면 예산을 빼고 개수를 늘린다.

가장 싼 다음 항목도 못 사면 그 뒤의 더 비싼 항목도 못 산다. 어떤 같은 개수 조합도 이 누적 가격보다 싸지 않다.

## 5. JavaScript 정답

<!-- solution -->
```js
function solution(prices, budget) {
  let count = 0;
  for (const price of [...prices].sort((a, b) => a - b)) {
    if (price > budget) break;
    budget -= price;
    count++;
  }
  return count;
}
```

코드를 다시 읽을 때 각 변수와 갱신문을 위의 손풀이에 연결하자. 코드를 닫고 “어떤 정보만 남겼는가”를 설명한 뒤 직접 재작성한다.

## 6. 실수와 반례

‘만족도 최대’처럼 가치가 달라지면 싼 순 선택이 정답이라는 보장이 없다.

## 7. 복잡도

통상 시간 O(n log n), 복사 공간 O(n).

## 8. 다음 문제에서 꺼낼 판단

그리디를 쓰려면 ‘좋은 선택으로 바꿔도 나빠지지 않는가’를 설명한다.
