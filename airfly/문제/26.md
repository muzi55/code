# 26. 세 장으로 만드는 목표 합

[학습 지도](../README.md) · [접근법](../개념노트/01-문제를-읽고-풀이를-설계하는-법.md)

목표: 작은 입력에서 조합을 중복 없이 열거한다.  
권장 시간: 12~18분 · JS 함수형 문제 · 자체 제작 Lv.1 목표 연습

## 문제

서로 다른 세 인덱스를 골라 합이 target인 경우의 수를 반환하라. 값이 같아도 인덱스 조합이 다르면 다른 경우다.

### 입력·반환·제한

길이 3~60, 원소 -100~100 정수, target -300~300.

### 예시

- 입력 인자: `[[1,2,3,4],6]`
- 반환값: `1`
- 설명: [1,2,3,4]에서 합 6인 조합은 1,2,3 하나다.

## 코딩 전에 직접 적기

1. 반환해야 하는 것은 값, 개수, 위치, 배열 중 무엇인가?
2. 아래 첫 예시를 종이에 풀면 무엇을 기억해야 하는가?
3. 떠오른 풀이의 최대 반복 횟수를 제한과 비교해 보자.
4. 변수마다 “지금까지 처리한 무엇”인지 한 문장으로 쓰자.
5. 정답 코드 전에 아래 테스트 중 두 개를 손으로 계산하자.

함수 형태: `solution(nums, target)`. 직접 만든 JS 파일에서 구현하고 마지막에 `module.exports = solution;`을 붙이면 테스트할 수 있다.

```sh
node airfly/test.cjs 26 airfly/practice.cjs
```

## 1. 문제를 계산으로 번역하기

모든 i<j<k의 합을 검사한다.

## 2. 첫 풀이를 평가하고 방법 고르기

최대 조합 수는 60×59×58/6=34,220이라 삼중 반복도 충분하다. 복잡도 차수만 보고 탈락시키지 않는다.

## 3. 손으로 실행해 보기

[1,2,3,4] 조합 합은 6,7,8,9. target=6인 것은 첫 조합뿐.

## 4. 구현 순서와 맞는 이유

1. 첫 인덱스 i를 고른다.
2. j=i+1부터 고른다.
3. k=j+1부터 고른다.
4. 합이 맞으면 센다.

모든 세 인덱스 집합에는 증가하는 순서가 정확히 하나 존재하므로 중복이나 누락이 없다.

## 5. JavaScript 정답

<!-- solution -->
```js
function solution(nums, target) {
  let count = 0;
  for (let i = 0; i < nums.length; i++) {
    for (let j = i + 1; j < nums.length; j++) {
      for (let k = j + 1; k < nums.length; k++) {
        if (nums[i] + nums[j] + nums[k] === target) count++;
      }
    }
  }
  return count;
}
```

코드를 다시 읽을 때 각 변수와 갱신문을 위의 손풀이에 연결하자. 코드를 닫고 “어떤 정보만 남겼는가”를 설명한 뒤 직접 재작성한다.

## 6. 실수와 반례

같은 값이라고 Set으로 합치면 서로 다른 인덱스 조합을 잃는다.

## 7. 복잡도

시간 O(n³), 추가 공간 O(1).

## 8. 다음 문제에서 꺼낼 판단

복잡도는 차수와 실제 n을 함께 본다. 60과 100,000은 허용하는 풀이가 다르다.
