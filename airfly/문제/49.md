## 문제

단위가 1,5,10,50,100인 동전을 무제한 사용해 amount를 만드는 최소 동전 개수를 반환하라.

### 입력·반환·제한

0≤amount≤1,000,000,000 정수. 동전 종류는 고정이다.

### 예시

- 입력 인자: `[186]`
- 반환값: `7`
- 설명: 186=100+50+10×3+5+1이므로 7개다.

## 코딩 전에 직접 적기

1. 반환해야 하는 것은 값, 개수, 위치, 배열 중 무엇인가?
2. 아래 첫 예시를 종이에 풀면 무엇을 기억해야 하는가?
3. 떠오른 풀이의 최대 반복 횟수를 제한과 비교해 보자.
4. 변수마다 “지금까지 처리한 무엇”인지 한 문장으로 쓰자.
5. 정답 코드 전에 아래 테스트 중 두 개를 손으로 계산하자.

함수 형태: `solution(amount)`. 직접 만든 JS 파일에서 구현하고 마지막에 `module.exports = solution;`을 붙이면 테스트할 수 있다.

## 1. 문제를 계산으로 번역하기

100부터 내려오며 정수 몫만큼 사용하고 나머지를 다음 단위로 넘긴다.

## 2. 첫 풀이를 평가하고 방법 고르기

단위가 순서대로 다음 단위의 약수다. 작은 동전이 충분히 모이면 큰 동전 하나로 바꿔 개수를 줄일 수 있어 큰 단위 우선이 최적이다.

## 3. 손으로 실행해 보기

186: 100 1개→86, 50 1개→36, 10 3개→6, 5 1개→1, 1 1개→0. 총 7.

## 4. 구현 순서와 맞는 이유

1. 큰 단위 순서로 반복한다.
2. remaining/coin의 정수 몫을 개수에 더한다.
3. remaining%=coin으로 갱신한다.

작은 단위가 다음 큰 단위를 만들 만큼 모인 최적해는 더 적은 동전으로 교환 가능하므로 최적일 수 없다. 배수 체계에서 이 교환을 반복하면 큰 단위 우선 형태가 된다.

## 5. JavaScript 정답

<!-- solution -->
```js
function solution(amount) {
  let count = 0;
  for (const coin of [100, 50, 10, 5, 1]) {
    count += Math.floor(amount / coin);
    amount %= coin;
  }
  return count;
}
```

코드를 다시 읽을 때 각 변수와 갱신문을 위의 손풀이에 연결하자. 코드를 닫고 “어떤 정보만 남겼는가”를 설명한 뒤 직접 재작성한다.

## 6. 실수와 반례

임의 동전에 일반화하지 않는다. [1,3,4]로 6을 만들면 큰 동전 우선 4+1+1보다 3+3이 낫다.

## 7. 복잡도

동전 종류가 5개로 고정이므로 시간 O(1), 추가 공간 O(1). 한 개씩 빼는 구현은 금액에 비례할 수 있다.

## 8. 다음 문제에서 꺼낼 판단
