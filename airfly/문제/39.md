# 39. 며칠 동안의 지출 합

[학습 지도](../README.md) · [접근법](../개념노트/01-문제를-읽고-풀이를-설계하는-법.md)

목표: 반복 구간 질의를 전처리로 바꾼다.  
권장 시간: 12~18분 · JS 함수형 문제 · 자체 제작 Lv.1 목표 연습

## 문제

각 [left,right] 요청에 대해 costs의 0 기준 left~right 양끝 포함 합을 반환하라.

### 입력·반환·제한

costs 길이 1~100,000, 값 0~10,000. 요청 0~100,000개, 0≤left≤right<길이.

### 예시

- 입력 인자: `[[2,4,1,3],[[1,3],[0,0]]]`
- 반환값: `[8,2]`
- 설명: [2,4,1,3]의 1~3 합은 8이고 0~0 합은 2다.

## 코딩 전에 직접 적기

1. 반환해야 하는 것은 값, 개수, 위치, 배열 중 무엇인가?
2. 아래 첫 예시를 종이에 풀면 무엇을 기억해야 하는가?
3. 떠오른 풀이의 최대 반복 횟수를 제한과 비교해 보자.
4. 변수마다 “지금까지 처리한 무엇”인지 한 문장으로 쓰자.
5. 정답 코드 전에 아래 테스트 중 두 개를 손으로 계산하자.

함수 형태: `solution(costs, queries)`. 직접 만든 JS 파일에서 구현하고 마지막에 `module.exports = solution;`을 붙이면 테스트할 수 있다.

## 1. 문제를 계산으로 번역하기

구간 합=prefix[right+1]-prefix[left].

## 2. 첫 풀이를 평가하고 방법 고르기

요청마다 더하면 최대 10^10번. 한 번 O(n) 전처리한 후 각 요청을 O(1)에 답한다.

## 3. 손으로 실행해 보기

costs=[2,4,1,3] → prefix=[0,2,6,7,10]. [1,3]은 10-2=8.

## 4. 구현 순서와 맞는 이유

1. 길이 n+1의 prefix를 만든다.
2. prefix[i+1]=prefix[i]+costs[i].
3. 각 요청에서 앞부분 합을 뺀다.

right까지의 합에서 left 이전의 합을 빼면 두 경계 사이만 정확히 남는다.

## 5. JavaScript 정답

<!-- solution -->
```js
function solution(costs, queries) {
  const prefix = [0];
  for (let i = 0; i < costs.length; i++) prefix.push(prefix[i] + costs[i]);
  return queries.map(([left, right]) => prefix[right + 1] - prefix[left]);
}
```

코드를 다시 읽을 때 각 변수와 갱신문을 위의 손풀이에 연결하자. 코드를 닫고 “어떤 정보만 남겼는가”를 설명한 뒤 직접 재작성한다.

## 6. 실수와 반례

prefix[right]-prefix[left]는 right 원소가 빠진다. left=0도 prefix[0] 덕분에 같은 식으로 처리한다.

## 7. 복잡도

시간 O(n+q), prefix O(n), 반환 O(q). 합 최댓값 10^9.

## 8. 다음 문제에서 꺼낼 판단

배열이 고정이고 같은 종류의 구간 질문이 많으면 누적합을 후보로 둔다.
