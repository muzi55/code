# 24. 구간 안의 k번째 가격

## 문제

각 [start,end,k] 요청마다 prices의 start번째부터 end번째까지 양끝 포함 구간을 복사·오름차순 정렬한 뒤 k번째 값을 구하라. 요청별 답을 배열로 반환하라.

### 입력·반환·제한

prices 길이 1~100, 요청 1~100개. 가격 0~1,000. 1≤start≤end≤길이, 1≤k≤end-start+1.

### 예시

- 입력 인자: `[[8,7,3,9,2],[[2,5,2]]]`
- 반환값: `[3]`
- 설명: 2~5번째는 [7,3,9,2], 정렬하면 [2,3,7,9]라 두 번째는 3.

## 코딩 전에 직접 적기

1. 반환해야 하는 것은 값, 개수, 위치, 배열 중 무엇인가?

5. 정답 코드 전에 아래 테스트 중 두 개를 손으로 계산하자.

함수 형태: `solution(prices, queries)`. 직접 만든 JS 파일에서 구현하고 마지막에 `module.exports = solution;`을 붙이면 테스트할 수 있다.

## 1. 문제를 계산으로 번역하기

slice(start-1,end)를 정렬하고 [k-1]을 읽는다.

## 2. 첫 풀이를 평가하고 방법 고르기

요청마다 짧은 구간을 정렬해도 충분하다. 전체를 먼저 정렬하면 원래 위치 기준의 구간이 사라진다.

## 3. 손으로 실행해 보기

prices=[8,7,3,9,2], [2,5,2] → slice(1,5) → [7,3,9,2] → [2,3,7,9] → 3.

## 4. 구현 순서와 맞는 이유

1. 요청을 구조 분해한다.
2. start만 1을 빼서 slice한다.
3. 정렬 후 k-1을 읽는다.

원래 end번째는 인덱스 end-1이다. 끝 미포함 경계를 end로 두면 정확히 포함된다.

## 5. JavaScript 정답

<!-- solution -->
```js
function solution(prices, queries) {
  return queries.map(([start, end, k]) => {
    const part = prices.slice(start - 1, end).sort((a, b) => a - b);
    return part[k - 1];
  });
}
```

코드를 다시 읽을 때 각 변수와 갱신문을 위의 손풀이에 연결하자. 코드를 닫고 “어떤 정보만 남겼는가”를 설명한 뒤 직접 재작성한다.

## 6. 실수와 반례

slice(start-1,end-1)은 마지막 항목을 빠뜨린다. 원본 배열 정렬도 금지된다.

## 7. 복잡도

q=요청 수, n=가격 수. 통상 시간 O(q n log n), 구간 임시 공간 O(n), 결과 O(q).

## 8. 다음 문제에서 꺼낼 판단

문제의 순번과 코드의 인덱스를 먼저 종이에 대응시킨다.
