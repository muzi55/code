# 36. 잔액을 넘는 결제 거절

[학습 지도](../README.md) · [접근법](../개념노트/01-문제를-읽고-풀이를-설계하는-법.md)

권장 시간: 12~18분 · JS 함수형 문제 · 자체 제작 Lv.1 목표 연습

## 문제

결제 요청을 순서대로 처리한다. 금액이 현재 잔액 이하면 승인하고 잔액에서 뺀다. 초과하면 거절하고 다음 요청을 계속 처리한다. [최종 잔액,승인 수]를 반환하라.

### 입력·반환·제한

balance 0~1,000,000,000. 요청 0~100,000개, 금액 1~10,000 정수.

### 예시

- 입력 인자: `[10,[7,5,3]]`
- 반환값: `[0,2]`
- 설명: 10에서 7 승인→3, 5 거절→3, 3 승인→0. 두 건 승인.

## 코딩 전에 직접 적기

1. 반환해야 하는 것은 값, 개수, 위치, 배열 중 무엇인가?
2. 아래 첫 예시를 종이에 풀면 무엇을 기억해야 하는가?
3. 떠오른 풀이의 최대 반복 횟수를 제한과 비교해 보자.
4. 변수마다 “지금까지 처리한 무엇”인지 한 문장으로 쓰자.
5. 정답 코드 전에 아래 테스트 중 두 개를 손으로 계산하자.

함수 형태: `solution(balance, payments)`. 직접 만든 JS 파일에서 구현하고 마지막에 `module.exports = solution;`을 붙이면 테스트할 수 있다.

## 1. 문제를 계산으로 번역하기

각 요청에 대해 가능한지 검사한 뒤 두 상태를 함께 바꾼다.

## 2. 첫 풀이를 평가하고 방법 고르기

정렬하면 요청 순서가 달라져 결과가 바뀐다. 원문 규칙 그대로 한 번 실행한다.

## 3. 손으로 실행해 보기

[7,5,3]: (10,0)→(3,1)→(3,1)→(0,2).

## 4. 구현 순서와 맞는 이유

1. 승인 수를 0으로 둔다.
2. 금액≤잔액이면 잔액을 빼고 승인 수 증가.
3. 아니면 상태를 유지하고 계속한다.

각 단계에서 승인 조건과 잔액 변화가 실제 처리 규칙과 일치한다.

## 5. JavaScript 정답

<!-- solution -->
```js
function solution(balance, payments) {
  let approved = 0;
  for (const payment of payments) {
    if (payment <= balance) {
      balance -= payment;
      approved++;
    }
  }
  return [balance, approved];
}
```

코드를 다시 읽을 때 각 변수와 갱신문을 위의 손풀이에 연결하자. 코드를 닫고 “어떤 정보만 남겼는가”를 설명한 뒤 직접 재작성한다.

## 6. 실수와 반례

거절 시 break하면 뒤의 작은 결제도 처리하지 못한다. 먼저 빼고 검사하면 거절 복구가 필요해진다.

## 7. 복잡도

시간 O(n), 추가 공간 O(1).

## 8. 다음 문제에서 꺼낼 판단

상태 변경 전에 가능 조건을 확인하면 되돌리기 코드를 줄일 수 있다.
