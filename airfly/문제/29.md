# 29. 정렬된 두 가격의 목표 합

[학습 지도](../README.md) · [접근법](../개념노트/01-문제를-읽고-풀이를-설계하는-법.md)

목표: 포인터를 움직여도 후보를 놓치지 않는 이유를 이해한다.  
권장 시간: 12~18분 · JS 함수형 문제 · 자체 제작 Lv.1 목표 연습

## 문제

오름차순 정렬된 prices에서 서로 다른 두 인덱스의 합이 target인 쌍이 있는지 반환하라.

### 입력·반환·제한

길이 0~100,000, 가격 0~1,000,000, target 0~2,000,000.

### 예시

- 입력 인자: `[[1,3,4,8],9]`
- 반환값: `true`
- 설명: [1,3,4,8]에서 1+8=9다.

## 코딩 전에 직접 적기

1. 반환해야 하는 것은 값, 개수, 위치, 배열 중 무엇인가?
2. 아래 첫 예시를 종이에 풀면 무엇을 기억해야 하는가?
3. 떠오른 풀이의 최대 반복 횟수를 제한과 비교해 보자.
4. 변수마다 “지금까지 처리한 무엇”인지 한 문장으로 쓰자.
5. 정답 코드 전에 아래 테스트 중 두 개를 손으로 계산하자.

함수 형태: `solution(prices, target)`. 직접 만든 JS 파일에서 구현하고 마지막에 `module.exports = solution;`을 붙이면 테스트할 수 있다.

## 1. 문제를 계산으로 번역하기

합이 작으면 작은 쪽을 키우고, 크면 큰 쪽을 줄인다.

## 2. 첫 풀이를 평가하고 방법 고르기

이미 정렬되어 있으므로 Set 없이 두 포인터로 O(n), 추가 공간 O(1)에 풀 수 있다. 정렬이라는 전제가 핵심이다.

## 3. 손으로 실행해 보기

[1,3,4,8],7: 1+8=9→right 감소. 1+4=5→left 증가. 3+4=7→성공.

## 4. 구현 순서와 맞는 이유

1. 양끝에서 시작한다.
2. 합이 맞으면 true.
3. 작으면 left++, 크면 right--.
4. 두 인덱스가 만나면 false.

합이 작으면 현재 left는 어떤 더 작은 right와도 목표가 안 된다. 합이 크면 현재 right는 어떤 더 큰 left와도 목표가 안 된다.

## 5. JavaScript 정답

<!-- solution -->
```js
function solution(prices, target) {
  let left = 0;
  let right = prices.length - 1;
  while (left < right) {
    const sum = prices[left] + prices[right];
    if (sum === target) return true;
    if (sum < target) left++;
    else right--;
  }
  return false;
}
```

코드를 다시 읽을 때 각 변수와 갱신문을 위의 손풀이에 연결하자. 코드를 닫고 “어떤 정보만 남겼는가”를 설명한 뒤 직접 재작성한다.

## 6. 실수와 반례

left<=right이면 한 원소를 두 번 사용할 수 있다. 정렬되지 않은 입력에는 이동 근거가 없다.

## 7. 복잡도

각 포인터가 한 방향으로만 이동하므로 시간 O(n), 추가 공간 O(1).

## 8. 다음 문제에서 꺼낼 판단
